# 通用图片转换

各栏目统一调用 `ConvertRaw.get_images_url` / `get_images_path`，底层由
`src/utils/images.ts` 维护一份惰性图片索引和按输出目录隔离的路径冲突登记。
新栏目中的 `archive_image` 只包装资源名、用途和补提取清单，不再单独查找或复制图片。

- 同名 PNG 按像素面积、文件字节数、路径字典序依次择优；索引检查 PNG 文件头和尺寸。
  完整 CRC、解压及扫描线校验仍由图片导入工具负责，不以文件头检查代替。
- 首次复制使用指定路径；不同文件争用同一路径时才加 `_1` 等尾缀，同一文件重复调用保持路径。
- `get_images_url(name, target, {output, nullable:true})` 支持独立输出目录，失败返回 `null`。
  旧有二参数调用及 `get_images_path` 保持字符串接口，失败返回空字符串，而不是不存在的 URL。
- 失败通过 `get_failed_images_list()` 汇总。内联图片失败时不生成空 `<img>`。
- 重新生成时会重新复制，避免文件已被清理但仍由进程缓存返回 URL。

旧流程首次就追加 `_1` 的行为已修正，因此旧栏目下次生成时，部分图片 URL 会回到无编号路径。
此次重构不批量重生成旧栏目，也不删除其已有图片；新栏目路径保持不变。

运行 `npm run check:images` 检查同名择优、路径碰撞、多输出目录、缺图、复制失败及兼容接口。
