# 尘歌壶、七圣召唤与千星奇域

本轮为原始文本研究页面的第一版，源数据范围与 Project #13、#14、#16 一致。

2026-10-30 清理：Wiki 不再导出摆设套装 `layout` 坐标，前端移除已停用的全部话题和
源文件原句模式，仅保留复用任务/NPC 流程的条件浏览。相应翻译、旧插槽、样式和包装函数
同步移除。genshin-db 及提取层的布局、原始对白和其他资料不变；查询、分支流程、
图片提取清单与仍有维护用途的溯源数据保留。
genshin-db 从源表提取名录，wiki-data 按 `src/data` 中显式目录选择条目并确定英文 ID。
维护规则见 [导出目录](archive_directories.md)。领域细节见
[尘歌壶](serenitea.md)、[七圣召唤](tcg.md)、[千星奇域](miliastra.md)。

## 生成与校验

先在 GenshinData-scripts 运行 `npm run export:archives`，再在 genshin-db 运行
`npm run makeIndex -- --folders serenitea tcg miliastra --languages ChineseSimplified English`。
wiki-data 只查询已提取的数据；完整分层与任务字幕流程见 [data_pipeline.md](data_pipeline.md)。

```text
npm run gen:archives
npm run gen:archives -- D:/Inteyvat-Wiki/data
npm run gen:archives -- ./data miliastra
npm run check:archives
npx tsx scripts/check_serenitea.ts
npx tsx scripts/check_tcg.ts
npx tsx scripts/check_miliastra.ts
npx tsx scripts/check_archive_dialogues.ts
```

默认生成中英文。目标目录仅更新所选分类的 `items`、`pages.json` 和公共 ID 索引，
不覆盖其他分类。常规 `index.ts` 也已接入三类生成器。

原始提取由 GenshinData-scripts 的 `extract/archives` 完成，包括源表、混淆字段、
普通/Medium TextMap、原始对白及资源关系；结果通过 genshin-db 的
`serenitea`、`tcg`、`miliastra` 查询入口提供。wiki-data 的 `utils/archive.ts`
仅负责站内关系、已提取图片匹配和既有对话展示格式转换，不读源数据或提取脚本配置。
不安全的 64 位整数在提取层保留为十进制字符串，没有执行游戏 Lua。

Wiki 发布范围可小于上游原始名录：尘歌壶从 2755 条中排除 2 个壶灵及 121 条角色摆设，
发布中英各 2632 页。角色摆设使用上游明确的角色→摆设关系识别，不新增源表解析；
被移除的关联只保留溯源引用，不生成页面链接。

`source.hashes` 仅为 TextMap 哈希，资源及其他关系放在 `source.references`。
来源、原始关系和诊断是内部溯源信息，不当作游戏设定正文展示。
关联已有页面时必须能解析到实际页面，不能凭同名或猜测制造链接。

## 图片

输入仍为按需提取的 `src/images`。存在的 PNG 复制到目标 `images`，不存在的图片
保留源名与 `url: null`；不生成无效 URL，也不把“未提取”当作游戏资产不存在。
独立生成脚本会输出 `common/<category>/assets.json`，可用于补提取图片。
生成 JSON、图片和临时检查产物不加入 Git。

2026-10-22 使用本地 AnimeStudio 和 `genshin_7.1.map` 从 7.1 客户端补提取，
新增 5505 个可展示的静态 PNG：尘歌壶 2310、七圣召唤 2054、千星奇域 1141。
按清单中的源名精确匹配，不用相似名称猜配数字哈希；只导入纹理/精灵，不导入模型或动画。
优先采用 Sprite 的游戏裁切边界，重复资源选择较高分辨率，只有纹理的背景图保留纹理原图。
新图片单独存放于 `src/images/archive-7.1`，不覆盖此前按需提取的文件。
Spine/Prefab 配置碰巧同名的拼图纹理只留在临时提取目录，不作为整张图片展示。
匹配、导出及导入报告在忽略的 `tmp/archive-images-*` 中；不影响源文及原始资源引用。

## 页面与接口

前端入口为 `/serenitea`、`/tcg`、`/miliastra`，详情页使用源 ID。
接口为 `/api/archive/<category>` 与 `/api/archive/<category>/<id>`，沿用现有语言、
用户文本设置和公共 ID 校验。新栏目共用 Element Plus 卡片、正文复制、搜索、分类、
分页及关系展示；对白复用任务/NPC的条件、选项、显示模式与复制组件。
无法取得运行时值的数字占位符（如 `{0}`）保留原始标记，不猜测替换值。
游戏颜色标记统一转为 HTML span，未知运行时颜色继承正文颜色并以 `data-source-color`
保留原标记。对白继续复用任务/NPC组件；标题及条件文字使用共用富文本组件，不直接插值 HTML。
图片以一张主图与缩略图切换，放大从当前图片开始；不拉伸原图，不把整列大图插在正文之前。
详情的源分类、获取途径、解锁说明、品阶、体型、颜色、部件类型等短字段及站内关联
统一放在主信息卡的 `el-descriptions` 中；短正文同样作为表格行，长正文才独立分卡。
长度判断使用去除富文本标记后的显示宽度；同标题、同类型的连续长文段落同卡保序，
例如教程各平台版本不会拆散或彼此混排。原始数据、单段复制和全部文本复制不因排版而截断。
短字段不显示逐项复制按钮，长文及对话保留复制；套装俯视布局示意不再展示。

列表复用筛选逻辑，但通过 `ArchiveListEntry` 和 `archive_list_layout` 按栏目/条目类型选取排版，
不再统一使用大图卡片：卡牌/头像为密集图片网格，摆设/装扮/形录为方形大图与下方标题，
洞天/套装/名片/牌桌为宽幅预览，牌手/成就为紧凑条目，壶内角色为名称索引，
关卡/阅读提示/教程/奇域文本为文字行（教程可附小缩略图）；成就集合参考角色列表，
使用居中大图与下方标题，不重复显示类型标记。大图网格按列表实际可用宽度（扣除侧栏）
从 6/4/3 列收为 2 列，极窄内容区为 1 列，
长标题最多显示 3 行、悬停保留完整名称，并有键盘焦点提示。
尘歌壶摆设缩略图居中，宽度为卡片内容区的 80%、最大 120px；洞天和摆设套装
横图高度为 150–190px。尺寸规则仅作用于对应类型，不改变其他栏目的图片。
没有可用图片或加载失败时回退紧凑布局，不保留空图区域和缺图文案；阅读提示不展示类别图标。
列表不再提供混合的“全部”分类，默认展示首个具体分类；旧 `type=all` 或无效类型网址回退首类。
列表省略重复类型徽标；教程范围提示只在对应分类显示。客户端邮件模板不再导出，角色邮件仍未完成。
摘要仅在列表裁切，详情及导出原文不受影响；搜索、源分类、多标签 AND、分页和 URL 状态继续共用。
默认“全部话题”保留所有源 Talk，不按解锁条件隐藏话题；每段独立复用任务流程引擎，
沿实际连接展示当前选择的分支，不把互斥回答串成连续对白。段内条件继续使用公共条件控件，
变量和选择不会在不同话题之间串用。“按条件浏览”保留实际入口与显式后继菜单。
另有明确标注的“源文本”视图，保留包括未接入演出的节点在内的所有原句；源文件顺序不是
游戏中的对话顺序。页面“复制全部文本”始终包含全部源句，不受当前选项影响。
菜单标签使用源 `initDialog` 对应的话题标题，不能用演出入口的第一句 NPC 回答代替。
壶内角色及七圣召唤对白只保留“按条件浏览”；壶内角色与七圣关卡的列表和详情隐藏图片及缺图占位。

首版不含种子、玉帛、图纸；不含七圣技能/效果/规则独立资料；不含奇域表情、动作、
传送、教程、音乐音效和其他创作素材。源记录缺文、历史空事件和未闭合的资源关系
继续保留诊断，不将“可以打开页面”等同于全部研究资料已覆盖。
