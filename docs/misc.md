# 杂项统一导出

杂项按 `GenshinData-scripts → genshin-db.misc() → wiki-data → Wiki` 提取。
本仓库不读取游戏源表、TextMap、客户端包或 Lua，也不从中文名称推断外键。

## 一种页面类型

`src/types/misc.ts` 定义唯一的 `MiscItem`：名称、类型、描述、文本分节、图片、
关联资料和来源。不同类型只通过 `type` 区分，不为每类建立独立页面数据结构，
也不引入对话、布局或奖励/成本数值字段。

genshin-db 的源记录 ID 仍为 `类型-源ID`；Wiki 导出由 `src/data/misc.js` 显式目录控制，
目录键为跨语言共用的英文 ID，值为源记录 ID。同名记录保留独立身份。
完整维护规则见 [archive_directories.md](archive_directories.md)。
测试、缺文记录的显示状态由上游保留，不能因此伪造名称或正文。
教程各平台内容使用独立分节，不把互斥平台段落当作连续剧情。
列表摘要可由同平台分节拼接；详情与整条复制只在内容完全重复时省去摘要，
不合并、删除原始分节，也不复制只有标题的空分节。
获取方式、发件人、标题变体等短字段与关联标签放入主信息卡的 descriptions 表格。
仅长正文独立分卡，同平台连续段落在卡内保持原顺序；这只是展示分组，不修改导出文本。

范围：成就、成就集合、名片、头像、头像框、探索派遣、豪斗旅纪、加载提示和教程。
成就集合使用 AchievementGoal 的真实 ID（默认值 0 为天地万象），按源 orderId 排序；
集合与保留的成就逐条双向关联，不因同名或多阶段成就合并身份，不纳入奖励数值。
成就描述中的 `{param0}` 由上游按各阶段的源 `progress` 补全；wiki-data 直接保留
补全后的描述，不读取源表、不推算数字，也不新增独立进度数值字段。
详情不再显示“来源详情”折叠区，但 source、hashes、references 和诊断仍保留在数据中。
成就集合的下属成就在主信息区下方单独展示名称和完整描述，按源关系顺序排列，
支持本集合搜索和每页 40 条分页；通过现有 misc 列表接口一次取得摘要，不逐条请求详情。
下属成就不再重复显示为主信息表中的关系标签；列表请求失败仍保留原成员名称与链接，并提供重试。
客户端邮件模板已从导出及页面入口移除，旧地址返回 404；角色历史来信仍未完成，
不能用系统模板宣称已覆盖生日邮件等服务器历史内容。原始 Mail 源表保留不动。
豪斗旅纪也不等于一般具名特殊敌人。此前暂缓的千星操作提示/教程不借此扩展。

图片只匹配 `src/images` 中真实存在的 PNG；仅有资源名或精确哈希的图片保留
`url: null`，不生成虚假网址。资源清单位于 `data/common/misc/assets.json`。
已有页面关联必须通过真实源 ID 和实际页面清单确认；未解析关联保留来源和诊断，
有名称的源分组/地区等仍作为非链接标签展示，不按同名猜链接或丢弃原文。
不会修改 genshin-db 的缓存对象。

## 生成与验证

先在 GenshinData-scripts 运行 `npm run export:misc`，再在 genshin-db 运行：

```text
npm run makeIndex -- --folders misc --languages ChineseSimplified English
```

本仓库：

```text
npm run gen:misc
npm run check:misc
```

当前中英各 5,744 条：成就 1,854、成就集合 73、名片 293、头像 188、头像框 12、探索派遣 48、
豪斗旅纪 13、加载提示 995、教程 2,268。
原始名称为空的教程不补写标题；有正文或图片的仍可浏览，界面单独标明缺少原始名称。

定向生成到前端数据目录：

```text
npm run gen:misc -- D:/Inteyvat-Wiki/data
```

启动前端本地正式预览后，可验证接口和实际图片响应：

```text
npm run check:misc:api -- http://127.0.0.1:4010
```

此前按清单用 AnimeStudio 精确名称匹配并提取 4,000 张 PNG，验证后放入新的
`src/images/misc-7.1`，未覆盖已有图片。当时资源清单共 11,614 个条目级引用，其中

头像框等尚未确认的哈希不会猜配图片；提取中间产物保留在忽略的 `tmp` 目录。

测试包含统一类型、双语 ID、图关系、真实图片、缓存不可变和禁止直读源数据断言。
缺少上游查询或索引时明确报错，不回退到原始目录。生成数据、图片和缓存不加入代码提交。

### 同名图片重新提取

`scripts/prepare_misc_images.ps1 -WorkDirectory <新的绝对工作目录>` 按当前资源清单
检查全部图片引用（包含已导入项），生成准备报告与提取计划，不自动执行提取。
它仅匹配完整资源名，优先 Sprite、缺少 Sprite 才使用同名 Texture2D；不会把承载
Sprite 的整张图集当作该图片。AnimeStudio 使用 `--group_assets BySource`，将不同
来源文件中的同名候选分目录保留，避免先落盘的小图导致后续大图被跳过。

执行计划的全部批次并核验后，运行：

```text
node scripts/import_misc_images.cjs --work <工作目录> --output-name <新的图片目录名> --apply
npm run check:misc:images
```

导入会校验 PNG 内容、CRC 和尺寸，优先像素面积、其次文件字节数，等值时按路径
稳定选取；所有候选和最终选择写入工作目录报告。新图导入全新 `src/images` 子目录，
不覆盖旧图或旧提取结果。Wiki 数据导出扫描同名 PNG 时使用同样的优先级，
所以高压缩的大分辨率图片不会因文件更小而输给低分辨率图片。随后定向生成杂项
到 wiki-data 和前端数据目录；正式预览的静态图片还需重新构建才更新。
